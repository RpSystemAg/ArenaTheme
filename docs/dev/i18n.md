# i18n — flusso di rilascio e adapter (H42/G11)

## 1. Il POT si rigenera a ogni release

```bash
node tools/make-pot.mjs           # rigenera theme + plugin pot
node tools/make-pot.mjs --check   # CI: fallisce se i pot committati sono stantii
```

Output committati:

- `theme/arena-commerce/languages/arena-commerce.pot`
- `plugin/arena-engine/languages/arena-engine.pot`

Il tool estrae `__`, `_e`, `esc_html__`, `esc_html_e`, `esc_attr__`,
`esc_attr_e`, `_x`, `_ex`, `esc_html_x`, `esc_attr_x`, `_n`, `_nx` con il
text domain corretto (`arena-commerce` / `arena-engine`). Una chiamata con il
domain sbagliato fallisce il gate G11.

## 2. Zero stringhe non traducibili

- Ogni stringa visibile all'utente nel PHP passa da gettext.
- Le stringhe consumate a runtime dai moduli JS (carrello, ricerca, dark
  mode, load-more) vivono nel **blocco JSON di configurazione** emesso in
  `wp_head` e sono registrate negli adapter (qui sotto), così WPML/Polylang
  possono tradurle come stringhe di tema.
- I contenuti dei kit non passano da gettext: ogni kit porta le proprie
  mappe `i18n.en_US` + `i18n.it_IT` complete (parità di chiavi verificata
  dal gate G11/G8). Questo è deliberato: il contenuto demo è *dato*, non UI.

## 3. Adapter WPML / Polylang

`plugin/arena-engine/includes/i18n/class-integrations.php`:

- si registra **solo** quando WPML (`wpml_loaded`, `ICL_SITEPRESS_VERSION`) o
  Polylang (`PLL()`, `POLYLANG_VERSION`) è attivo — zero costo altrimenti;
- registra le stringhe runtime con `wpml_register_single_string` /
  `pll_register_string` nel gruppo `arena-engine`;
- fornisce `Integrations::runtime_strings()` come lista unica (nessuna
  duplicazione).

Estensione documentata: aggiungere una stringa a `runtime_strings()` —
apparirà sia nel blocco JSON sia negli adapter, senza toccare altrove.

## 4. Verifica

- Statica (ogni commit): `node tests/g11-i18n.test.mjs` — pot freschi,
  domain puliti, adapter presenti e guardati, parità locale dei kit.
- Runtime (wp-env): attivare WPML o Polylang e verificare che le stringhe
  del gruppo `arena-engine` appaiano nell'elenco traduzioni (il caso di test
  è descritto in `docs/utente/traduzioni.md`).

## 5. Tag del tema

`style.css` dichiara `rtl-language-support` e `translation-ready`: entrambi
sparati dai file reali (fogoni RTL generati + pot committati) — AP11 chiusa.
